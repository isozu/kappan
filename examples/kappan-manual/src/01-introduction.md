# 第1章 はじめに

本書は、Markdown から EPUB 3.3 を生成するツール **Kappan**（{活版|かっぱん}）の利用者向けマニュアルである。最小限の手順で最初の電子書籍を出力するところから、本格的な書籍プロジェクトの構成までを扱う。

Kappan という名は、近代日本の出版を支えた{金属活字組版|きんぞくかつじくみはん}の技法に由来する。{文選工|もんせんこう}が活字を拾い、{植字工|しょくじこう}が版に組むという分業構造が、本ツールのプラグインアーキテクチャと[響き合っている]{.kenten}。

## 1.1 Kappan とは

Kappan は、商業出版に耐える品質の EPUB を Markdown 一本から組み上げることを目的とした、Node.js と TypeScript で実装されたコマンドラインツールである。設計理念は次の五つに集約される。

- **AST 中心主義**：文字列置換ではなく、抽象構文木（AST）上での変換を原則とする
- **Web 標準準拠**：EPUB 3.3、WAI-ARIA、schema.org など W3C 標準を最優先する
- **日本語組版のファーストクラス対応**：ルビ、縦組み、禁則処理を後付けではなく初期から扱う
- **アクセシビリティの非妥協**：EPUB Accessibility 1.1 への準拠を必須要件とする
- **徹底した仕上がり品質**：EPUBCheck エラーゼロを最低ラインとし、商業ストアへの直接入稿を目指す

## 1.2 なぜ Markdown から EPUB か

電子書籍を制作する手段は数多くある。Word、InDesign、Sigil、Re:VIEW、Pandoc、Vivliostyle など、それぞれに長所がある。それでも Markdown から EPUB を組む経路に独自の価値があるのは、次の理由による。

1. **テキスト中心の制作フロー**：原稿はバージョン管理（Git）と相性が良い形で書ける
2. **既存資産の再利用**：Obsidian、GitHub、Notion、各種 CMS の Markdown 資産がそのまま入力になる
3. **CI/CD との親和性**：自動化されたビルドパイプラインで再現性のある成果物を得られる
4. **共同編集の容易さ**：Pull Request ベースの編集レビューが成立する

Kappan はこれらの利点を保ったまま、商業 EPUB に要求される品質（日本語組版、アクセシビリティ、リーダー互換性）を担保することを目指している。

## 1.3 本書の対象読者

本書は次の読者を想定している。

- 技術書、小説、エッセイ等を Markdown で執筆し、EPUB として配布したい書籍著者
- Re:VIEW や Sigil から Kappan への移行を検討している既存ユーザー
- 出版社・編集者で電子書籍の制作フローを刷新したい関係者
- Kappan のプラグインやテーマを書きたい開発者（プラグイン作者向けの詳細は別文書）

プログラミングの予備知識は最低限で読めるよう配慮した。ターミナル操作と Markdown の基本構文を知っていれば十分である。

## 1.4 本書の構成

本書は以下の章立てとなる。

- 第2章「環境の準備」：Node.js、pnpm、Java の用意と Kappan の取得
- 第3章「最初の本を作る」：最小構成の書籍プロジェクトを作って `kappan build` する
- 第4章「Markdown の書き方」：使える記法、画像、リンク、テーブル
- 第5章「設定リファレンス」：`kappan.config.ts` の全フィールド
- 第6章「アクセシビリティ」：必須化されている検証項目と自動付与されるメタデータ
- 第7章「EPUBCheck で検証する」：商業流通の最低ラインを満たすための手順
- 第8章「各ストアへの入稿」：Apple Books、Kindle、Kobo の特徴
- 第9章「制約と今後の予定」：現時点で未対応の機能と今後の予定
- 第10章「さらに学ぶ」：参考資料とコントリビューションの方法

## 1.5 バージョンの位置付け

本書は Kappan のベータ版を対象としている。`@kappan/*` パッケージは公開 API を凍結したうえで npm 公開され、semver を厳格に運用する。

本書中で「今後の予定」と記される機能は、本書の発行時点では実装されていない。
