# 第6章 アクセシビリティ

EPUB Accessibility 1.1 への準拠は Kappan の必須要件である。本章では、自動で検証される項目と、自動付与されるメタデータを整理する。

## 6.1 なぜアクセシビリティが必須か

電子書籍が広く読まれるためには、視覚障害者向けのスクリーンリーダー、認知特性に応じた読み上げ、ハイコントラスト表示など、多様な読書環境への配慮が欠かせない。これは倫理的要請であると同時に、商業流通の事実上の要件でもある。

- **欧州アクセシビリティ法（EAA）**：2025 年 6 月施行済み。EU 圏での電子書籍販売はアクセシビリティ準拠が要求される
- **改正障害者差別解消法（日本）**：2024 年 4 月施行済み。事業者の合理的配慮が法的義務となった
- **Apple Books の入稿要件**：アクセシビリティメタデータが欠落していると入稿審査で警告される

Kappan はこれらを必須化し、未充足のままビルドが完了することを認めない設計とした。

## 6.2 自動検証される項目

ビルド時に以下が自動的にチェックされる。

### 画像 alt 属性の必須化

すべての `<img>` 要素は `alt` 属性を持たなければならない。alt が無い場合、または空文字（`alt=""`）の場合はビルドが `BuildError` で中断する。

```markdown
![図1：システム構成](images/architecture.png)
```

例外として、装飾目的の画像で意味を持たないものは `role="presentation"` を付けて空 alt を許容できる。この場合は HTML 直書きが必要となるため、`unsafeHtml` の設定で許可する。

### 見出し階層の検証

見出し階層は連続していなければならない。たとえば `<h1>` の直後に `<h3>` が来る（`<h2>` を飛ばす）構造は警告となる。

```markdown
# 第1章 はじめに

### 1.1.1 詳細 ← h1 → h3 の飛びを警告
```

これは警告（warning）レベルなのでビルドは成功するが、スクリーンリーダー利用者の構造把握を妨げるため、修正することを強く推奨する。

## 6.3 自動付与されるメタデータ

OPF（package.opf）の metadata に schema.org のアクセシビリティ語彙が自動的に書き出される。設定で明示すれば、その値が優先される。明示しない場合、本文の構造から推定される。

### accessibilityFeature

書籍が備えるアクセシビリティ機能の一覧。自動推定される項目は次の通り。

| 値                     | 推定条件                                |
| ---------------------- | --------------------------------------- |
| `tableOfContents`      | 常に付与（nav doc が必須）              |
| `structuralNavigation` | 常に付与（見出し階層を持つため）        |
| `alternativeText`      | すべての画像に alt が付与されている場合 |
| `MathML`               | 本文中に `<math>` 要素がある場合        |

### accessMode

書籍の情報伝達手段。自動推定される項目は次の通り。

| 値        | 推定条件                           |
| --------- | ---------------------------------- |
| `textual` | 常に付与（本文が文字列であるため） |
| `visual`  | 画像または SVG が含まれる場合      |

### accessibilityHazard

書籍に含まれる視覚的・聴覚的ハザード。デフォルトは `none`（無し）。光感受性発作を誘発する映像など特殊なケースは、設定で明示的に指定する。

```typescript
accessibility: {
  hazards: ['none'],  // または 'flashing', 'motionSimulation', 'sound' など
}
```

### accessibilitySummary

人間可読のアクセシビリティ説明文。設定で明示しなければ、推定された features の組み合わせから自動生成される。例：

```
本書は次のアクセシビリティ機能を備えています：
構造的ナビゲーション、目次、画像の代替テキスト。
```

商業流通向けには、より詳細な説明（読み上げソフトウェアでの動作確認結果や、特定の障害種別への配慮など）を手動で記すことを推奨する。

## 6.4 設定での上書き

自動推定の結果に手を加えたい場合は、`kappan.config.ts` の `metadata.accessibility` で明示する。

```typescript
accessibility: {
  features: [
    'structuralNavigation',
    'tableOfContents',
    'alternativeText',
    'readingOrder',           // 手動で追加
    'displayTransformability',
  ],
  hazards: ['none'],
  summary: '本書はスクリーンリーダー Pico Voice での再生確認済みです。',
}
```

明示された値が完全に推定値を置き換える（部分マージではない）ことに注意。

## 6.5 ACE by DAISY との関係

EPUBCheck がパッケージ構造の検証を担うのに対し、**ACE（Accessibility Checker for EPUB）by DAISY** は、アクセシビリティ観点での網羅的な検証ツールとして広く使われている。Kappan は ACE 統合を備え、`--ace` フラグで検証を実行できる。

それまでの間も、生成された EPUB を手動で `ace <epub-file>` に通すことで、より詳細な検査が可能である。
