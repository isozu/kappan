# 第4章 Re:VIEW からの移行 {#ch04}

すでに Re:VIEW で書いた原稿があるなら、最初から書き直す必要はない。
Kappan は Re:VIEW プロジェクトを Markdown プロジェクトへ {変換|へんかん}する
移行コマンドを備えている。本章ではその使い方を概観する。

## 4.1 移行コマンド {#sec:migrate}

移行は 1 コマンドで完結する。Re:VIEW プロジェクトのディレクトリを指定し、
出力先を `--out` で与えるだけだ。

移行コマンドの実行 {#lst:migrate-cmd}

```shell
# before/ の Re:VIEW 原稿を after/ に Markdown 化する
pnpm kappan migrate before --out after --force
```

[@lst:migrate-cmd]を実行すると、`.re` ファイルが Markdown に、
`config.yml` と `catalog.yml` が `kappan.config.ts` に変換される。画像も
そのままコピーされる。

![移行の入出力](../assets/images/migrate.png){#fig:migrate}

[@fig:migrate]のとおり、入力（Re:VIEW プロジェクト）と出力（Kappan プロジェクト）は
一対一で対応する。変換の実例は、本リポジトリの `examples/showcase-migration/` で
{!ビフォーアフター|びふぉーあふたー!}として確認できる。

## 4.2 記法の対応

主要な Re:VIEW 記法は Markdown / Kappan 拡張記法へ機械的に変換される。

Re:VIEW 記法の対応 {#tbl:notation-map}

| Re:VIEW            | Kappan (Markdown)   |
| ------------------ | ------------------- |
| `@<b>{太字}`       | `**太字**`          |
| `@<ruby>{親,読}`   | `{親\|読}`          |
| `//list{ ... //}`  | ` ``` ` フェンス     |
| `@<fn>{id}`        | `[^id]`             |
| `catalog.yml`      | front-matter        |

[@tbl:notation-map]は対応の一部である。未対応の記法は変換後の
Markdown にコメントとして残るので、移行後に目視で追える[^ch4-unsupported]。

## 4.3 移行後にやること

変換はあくまで出発点である。Markdown 化された原稿に対して、本書で見た
{!索引|さくいん!}（`{!...!}`）や数式（`$$...$$`）を追記すれば、Kappan ならではの
機能をそのまま活かせる。

移行後のプラグイン構成 {#lst:post-migrate-config}

```typescript
// 移行後の kappan.config.ts にプラグインを足していく
plugins: [
  reviewCompat(),
  figureNumbering(),
  jpIndex(), // 索引を使うなら追加
  katexMath(), // 数式を使うなら追加
  kinsoku(),
];
```

[@lst:post-migrate-config]のように、必要なプラグインを足すだけで
本書と同じ表現力が手に入る。

> 移行ツールの価値は「完璧な変換」ではなく「書き直しをゼロにすること」にある。
> 残りの磨き込みは、新しい道具の上で気持ちよく進められる。
>
> — 移行を終えての所感

本書はここまで、横組み技術書に必要な要素を一通り見てきた。あとは実際に
`kappan.config.ts` を書き、原稿を流し込むだけである。

[^ch4-unsupported]: 未対応記法は `<!-- REVIEW-UNSUPPORTED: ... -->` というコメントで
    残る。移行レポート（`migration-report.md`）にも件数が集計されるため、
    対応漏れを見落としにくい。
